# Knowledge store

## Summary

A knowledge store is where Azure AI Search can persist enriched data from an enrichment pipeline as projections, including JSON objects, relational-style tables, or image files. (SRC-181 L218–222)

## The problem it solves

The search index is the primary queryable output, but enriched values can also be useful outside search: ETL integration, analysis and reporting, or saving images extracted during indexing. (SRC-181 L218–221) A knowledge store captures those enriched outputs for downstream use. (SRC-181 L222)

## Mental model

**Inference:** If the index is the searchable output, the knowledge store is the reusable by-product store. The same enrichment pipeline that fills the index can also project selected enriched data into forms that analytics and integration systems can consume. (SRC-181 L218–222)

## What the sources say

- The module introduction says learners will see how to use the knowledge store to persist enriched data for further analysis and integration with other systems. (SRC-130 L218)
- The service overview says Azure AI Search can store extracted insights in a knowledge store for analysis and integration. (SRC-261 L219–222)
- The knowledge-store unit says an index might be considered the primary output, but enriched data can be useful for JSON export, normalized relational schemas, and saving extracted embedded images as files. (SRC-181 L218–221)
- The knowledge store is defined in the skillset that encapsulates the enrichment pipeline and consists of projections of enriched data. (SRC-181 L222)
- When an indexer runs the pipeline to create or update an index, projections are generated and persisted in the knowledge store. (SRC-181 L222)
- The module assessment asks which projection produces a relational data schema for extracted fields. (SRC-176 L226)
- The module summary includes persisting enriched data in a knowledge store for further analysis and integration. (SRC-215 L218–219)

## How it works in Azure

The corpus frames the knowledge store as part of the skillset, not as a separate query index. The skillset encapsulates the enrichment pipeline, and its knowledge-store definition specifies projections. Those projections are materialized when the indexer runs. (SRC-181 L222)

Projection forms in the corpus are JSON objects, tables, and image files. (SRC-181 L222)

## Code and configuration

The corpus does not show knowledge-store JSON or an Azure Storage account configuration. It does state the placement and output types: define the knowledge store in the skillset, use projections of enriched data, and persist them when the indexer creates or updates an index. (SRC-181 L222)

## Decision boundaries

| **Inference:** Need | Use | Why |
|---|---|---|
| Query search results | [[search-indexes]] | The index is queried by client applications to retrieve, filter, and sort information. (SRC-187 L218–231) |
| Save enriched outputs for ETL, analytics, reporting, or extracted images | Knowledge store | It persists projections as JSON objects, tables, or image files. (SRC-181 L218–222) |
| Add language/OCR/entities/key phrases before output | [[ai-enrichment-skillsets]] | Skills create the enriched fields that can then be indexed or projected. (SRC-52 L218–232) |

**Inference:** If the exam clue says relational data schema for extracted fields, choose table projection rather than the search index itself. (SRC-181 L218–222; SRC-176 L226)

## Failure modes and misconceptions

- Treating the knowledge store as the primary query surface confuses it with the index; the source says the index might be considered the primary output. (SRC-181 L218)
- Treating a knowledge store as raw storage misses that it stores enriched projections generated by an enrichment pipeline. (SRC-181 L222)
- Assuming projections happen independently of indexing misses that projections are generated when an indexer runs the pipeline to create or update an index. (SRC-181 L222)

## Solution Engineering transfer

**Inference:** Ask whether the enriched outputs only need to answer search/RAG questions or whether they must feed reporting, ETL, image-file extraction, or another system. The latter points toward a knowledge store. (SRC-181 L218–222)
