## TL;DR

Azure Speech in Foundry Tools includes a Speech Translation API for translating spoken input and returning the translation as text or speech. (SRC-226 L12) Client code uses `SpeechTranslationConfig` to connect and configure languages, `AudioConfig` for the input stream, and `TranslationRecognizer` to perform speech translation. (SRC-226 L14–28) Speech-to-speech output can be generated by manual synthesis for multiple target languages or event-based synthesis for one-to-one translation. (SRC-226 L33–48)

## Key claims

- Azure Speech in Foundry Tools provides APIs for speech-enabled applications and agents. (SRC-226 L12)
- The Speech Translation API translates spoken input and can return translation as text or speech. (SRC-226 L12)
- Application code uses `TranslationRecognizer`, created with `SpeechTranslationConfig`, to support speech translation. (SRC-226 L14)
- `SpeechTranslationConfig` connects client code to an Azure Speech resource by endpoint or region. (SRC-226 L16–19)
- `SpeechTranslationConfig` configures source and target languages, while `AudioConfig` specifies the source audio stream. (SRC-226 L20–25)
- Manual synthesis combines translation recognition with `SpeechSynthesizer` output for each returned translation. (SRC-226 L33–41)
- Event-based synthesis captures translated audio from the `TranslationRecognizer` synthesizing event for one-to-one translation. (SRC-226 L42–50)

## How it works

For speech-to-text translation, the application connects to Azure Speech, sets the source speech-recognition language, adds one or more target languages, supplies an audio source such as the default microphone, and then calls the recognizer to return translated text values. (SRC-226 L16–30) For manual speech-to-speech translation, the application iterates through the translation result and uses `SpeechSynthesizer` with language-specific voices to synthesize each translated text string. (SRC-226 L33–41) For event-based speech-to-speech translation, the application configures a desired voice, subscribes to the `Synthesizing` event, retrieves the audio byte stream from the event result, and writes or plays the audio. (SRC-226 L42–50)


## Key terms

- `SpeechTranslationConfig` carries connection information and the language translation configuration. (SRC-226 L16–23)
- `AudioConfig` specifies the source audio stream, such as the default system microphone. (SRC-226 L21–25)
- `TranslationRecognizer` performs the configured translation operation. (SRC-226 L14; SRC-226 L26–28)
- Manual synthesis uses translated text results and then synthesizes each language with `SpeechSynthesizer`. (SRC-226 L35–41)
- Event-based synthesis captures translated audio from the `Synthesizing` event for a single target language. (SRC-226 L42–48)

## Decision boundaries and exam cues

- **Inference:** Choose `SpeechTranslationConfig` when asked which object specifies source and target languages for speech translation. (SRC-226 L20–23)
- **Inference:** Choose `AudioConfig` when the scenario asks where the audio input comes from. (SRC-226 L21–25)
- **Inference:** Choose `TranslationRecognizer` when the scenario asks which object executes the speech translation operation. (SRC-226 L14; SRC-226 L26–28)
- **Inference:** Use manual synthesis when multiple target languages must be synthesized from one spoken input. (SRC-226 L33–41)
- **Inference:** Use event-based synthesis for one source language to one target language when the translated audio stream must be captured as it is produced. (SRC-226 L42–48)
