## TL;DR

This is the official study guide for Exam AI-103 and is the authoritative source in this batch for audience profile, domain weights, update policy, preview-feature policy, and skills measured as of April 16, 2026 (SRC-191 L92–102). It defines the candidate as an Azure AI engineer who builds, manages, and deploys agents and AI solutions using Microsoft Foundry, with Python, general AI, generative AI, and Azure services familiarity (SRC-191 L103–112). The exam is split across five weighted domains: plan/manage Azure AI solutions, generative AI and agentic solutions, computer vision, text analysis, and information extraction (SRC-191 L113–119).

## Key claims

- The study guide helps candidates understand exam expectations, topic summaries, and resources for focused study (SRC-191 L92–93).
- Microsoft updates exams periodically and updates the English version first, with localized exams updated approximately eight weeks later where applicable (SRC-191 L95–97).
- The bullets under each skill illustrate assessment, and related topics may also be covered on the exam (SRC-191 L98–99).
- Most questions cover generally available features, but preview features may appear if commonly used (SRC-191 L100–101).
- Skills measured are stated as of April 16, 2026 (SRC-191 L102).
- The audience profile is an Azure AI engineer who builds, manages, and deploys agents and AI solutions with Microsoft Foundry (SRC-191 L103–104).
- Candidates should have Python app-development experience and familiarity with general AI, generative AI, and Azure services (SRC-191 L105).
- Responsibilities include planning/managing Azure AI solutions, implementing generative AI and agentic solutions, computer vision, text analysis, and information extraction (SRC-191 L106–111).
- The role collaborates with business stakeholders, solution architects, data scientists, DevOps engineers, and cloud security engineers (SRC-191 L112).
- The five domains and weights are: Plan and manage an Azure AI solution 25–30%, Implement generative AI and agentic solutions 30–35%, Implement computer vision solutions 10–15%, Implement text analysis solutions 10–15%, and Implement information extraction solutions 10–15% (SRC-191 L113–119).
- Microsoft recommends training and hands-on experience before taking the exam (SRC-191 L202–203).
- The page shows last updated on 04/14/2026 (SRC-191 L205–206).

## How it works

The study guide is organized as exam metadata first, then audience profile, a five-domain skills-at-a-glance section, and detailed skills/objectives under each domain (SRC-191 L92–201). It explicitly says the bullets under skills illustrate how Microsoft assesses the skill, so the objectives should be treated as assessment scope rather than a closed list of all possible wording (SRC-191 L98–99).

### Domain 1: Plan and manage an Azure AI solution (25–30%)

This domain contains four skill groups: choose Foundry services for generative AI and agents, set up AI solutions in Foundry, manage/monitor/secure AI systems, and implement responsible AI across generative AI and agentic systems (SRC-191 L119–139). Objectives include choosing models and Foundry services, retrieval/indexing methods, memory/tool/knowledge services, infrastructure, deployment options, model and agent deployments, CI/CD, quotas, performance, drift, safety events, grounding quality, ingestion quality, security, safety filters, evaluators, trace logging, provenance, approval workflows, oversight modes, constraints, and tool-access controls (SRC-191 L120–139).

### Domain 2: Implement generative AI and agentic solutions (30–35%)

This is the largest weighted domain and has three skill groups: build generative applications by using Foundry, build agents by using Foundry, and optimize/operationalize generative AI systems (SRC-191 L140–159). Objectives include deploying and consuming models, implementing RAG, designing workflows and tool-augmented or multistep pipelines, evaluating models and apps, using Foundry SDKs and connectors, connecting apps to Foundry projects, defining agent roles/goals/conversation/tool schemas, integrating retrieval/function-calling/memory, integrating tools, orchestrating multi-agent solutions, building autonomous or semiautonomous workflows with safeguards, monitoring agents, prompt and parameter tuning, reflection, chain-of-thought evaluations, self-critique, tracing, token analytics, safety signals, latency breakdowns, and orchestrating multiple models/flows/hybrid systems (SRC-191 L141–159).

### Domain 3: Implement computer vision solutions (10–15%)

This domain includes image/video generation, multimodal understanding workflows, and responsible AI for multimodal content (SRC-191 L160–179). Objectives cover text-prompt and reference-media image generation, video generation, inpainting and mask-based image editing, generated-video editing, generation controls, visual context analysis, captioning, visual Q&A, alt text and extended image descriptions, Content Understanding visual extraction, video analysis, single-task and pro-mode Content Understanding pipelines, object/component/region identification, unsafe visual-content filters, indirect prompt injection through embedded image text, and visual policy enforcement (SRC-191 L161–179).

### Domain 4: Implement text analysis solutions (10–15%)

This domain includes language-model text analysis and speech solutions (SRC-191 L180–190). Objectives cover entity/topic/summary/structured JSON extraction with generative prompting and Foundry Tools, sentiment/tone/safety/sensitive-content detection, Azure Translator or LLM-powered text translation, domain-output customization, speech-to-text and text-to-speech workflows for agentic interactions, speech as an agent modality including custom speech models, audio-input multimodal reasoning, and speech translation through language models and Foundry Tools (SRC-191 L181–190).

### Domain 5: Implement information extraction solutions (10–15%)

This domain includes retrieval/grounding pipelines and document content extraction (SRC-191 L191–201). Objectives cover ingesting and indexing documents/images/audio/video, semantic/hybrid/vector search, built-in and custom enrichment skills for text/images/layout, RAG ingestion including OCR, connecting retrieval to workflows and agent tools, multimodal OCR/layout/field extraction, grounded representations for agents and RAG through Content Understanding, and analyzers that produce structured or markdown outputs for downstream reasoning (SRC-191 L192–201).
